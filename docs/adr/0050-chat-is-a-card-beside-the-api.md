# Chat is a card beside the API

**Chat** is the card along the bottom of the signed-in workspace: one thread per shop, the same thread across Destinations, absent from the Landing page. It is not a Destination. [0042](./0042-remove-website-and-conversation.md) still holds for Website and for a Conversation Destination. There is no Silence and no unprompted job offer.

SnapSync runs the model on its own service and holds the key. The seller does not. The Railway API is the only caller, one authenticated call per message, as that seller. The service may request an act that message asked for. The API runs the existing operation, so the page's gates and job caps still hold. The Shopify token and the session cookie stay off the model service. SnapSync stores the thread, so any instance can take the next turn. A turn ends when the API has run or refused that message. A message sent during a turn waits. One message stops after 10 model calls. The thread says it stopped. Acts that already landed stay landed, and later ones do not run. Import's turn ends once Import has started. Talk and questions spend no Credit. The model bill is SnapSync's.

A message may ask for an act the seller can already perform on that shop, including confirm facts, generate, Accept, listing copy refresh, Bulk SEO, dismiss, regenerate a field, Selling, Inventory, Import, Push, Go live, a Trendyol Push, delete, Shop GPSR, and publications. The message has to supply the inputs the page would demand. A missing input is asked for, and nothing runs. A question changes nothing. Buying Credits, connecting or disconnecting a Channel, claiming a shop, cancelling a Plan, and choosing photos stay in the browser. Chat does not change the open Destination.

Accept from Chat is the same Accept, after that proposal is already in the thread, showing the same fields the page shows. Several named Accepts in one message are that many Accepts, in order, one Credit each. The first refusal stops the later acts. Words the seller quotes are typed listing copy. "Write the listing" is the generate job. "Put it live" is Go live.

We rejected a Conversation Destination, a WebSocket held open per shop, the model service calling Shopify with the seller's credentials, running the graph inside the Railway API, an uncapped model loop, and Accept in the same message that first shows the proposal.
