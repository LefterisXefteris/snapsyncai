handleDragEnd overId routing:
```tsx
// Within-group reorder: both active and over are item IDs in the same group
const activeGroup = groups.find(g => g.items.some(i => i.id === activeId));
const overGroup = groups.find(g => g.items.some(i => i.id === overId));

if (activeGroup && overGroup && activeGroup.id === overGroup.id) {
  // arrayMove within group
  return;
}

// Between-group: overId is a group ID OR "new-group"
// toGroup = next.find(g => g.id === overId)  ← only matches group IDs
```

ROOT CAUSE: When hovering over a thumbnail in another group, overId is a thumbnail item ID, not a group ID.
`next.find(g => g.id === overId)` returns undefined for item IDs → no move happens.

The `useDroppable` on the outer card div fires isOver correctly only when pointer is in empty space.
When pointer is over a SortableThumbnail, the SortableThumbnail's droppable surface wins and
overId in handleDragEnd becomes the thumbnail ID, not the group ID.

Fix strategy:
1. In handleDragEnd, after the within-group check fails, resolve `overId` to a group: first try
   direct group ID match, then fall back to finding which group contains an item with that ID.
   This makes drops on thumbnails in OTHER groups work correctly.
2. In DroppableGroup, add `scale-[1.02]` to the isOver className so the card scales up visually.
3. Keep the "Drop here" overlay as-is (already good visual feedback).
4. The isOver state on DroppableGroup already fires when hovering empty space — no structural change needed.
   The main bug is the between-group thumbnail-as-overId case in handleDragEnd.
