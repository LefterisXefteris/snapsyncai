<decisions>
- The current variant-family flow is functional but not yet strong enough for large fashion-heavy batches
- Apparel grouping should optimize for base-garment identity: silhouette, cut, graphic placement, construction, and shape, not just generic category similarity
- Different colors, sizes, angles, washes, and materials may be one family, but different graphics or base garment structures should usually remain separate
- The system must be truthful: if no meaningful merges happened, the UI should say so plainly
- Quality work should be guided by repeatable batch evaluation examples before further prompt tuning
</decisions>
</context>

  <files>server/routes.ts</files>
  <action>
Refactor the grouping pipeline for existing uploaded images so it behaves more like a practical agentic sorter than a single broad clustering pass.

**Pipeline direction:**
- Stage A: Build richer per-image descriptors from available metadata plus normalized filename/title/category context
- Stage B: Create coarse candidate buckets that reduce obviously unrelated comparisons
- Stage C: Run variant-family clustering within candidate buckets
- Stage D: Run a merge-verification pass across candidate families to catch split variants without merging unrelated products

**Important constraints:**
- Keep support for up to 200 images
- Avoid giant browser payloads
- Preserve deterministic fallback behavior when the model is uncertain
- Keep the response shape compatible with the existing workspace sorter
