  <action>
Add a new POST endpoint at `/api/images/auto-group` in server/routes.ts, placed after the regenerate-field endpoint (around line 3280). Use `requireAuth()` middleware.

**Request body:** The endpoint receives a JSON body with:
- `images`: array of `{ index: number, base64: string, mimeType: string, filename: string }` (up to 200 items)
- `productContext`: optional string (user's custom AI prompt)

**Algorithm — Batched Vision Grouping:**

1. Validate: require at least 2 images, max 200. Return 400 if invalid.
2. Set SSE headers (same pattern as generate-content endpoint).
3. Process images in batches of 15 (balances cost vs accuracy -- too many images per call reduces GPT accuracy):
   - For EACH batch, call `openai.chat.completions.create` with model `gpt-5.2`, `response_format: { type: "json_object" }`, max_completion_tokens: 2000.
   - The message content includes all batch images as `image_url` content parts (base64 data URLs).
   - System prompt (critical for accuracy):
     ```
     You are a product image grouping assistant for an e-commerce platform, specializing in clothing and fashion.

     You will receive multiple product images. Your job is to identify which images show the SAME product and group them together.

     Rules:
     - Same product in different colors = same group (they are variants)
     - Same product from different angles (front, back, detail, side) = same group
     - Different products = different groups
     - If an image is ambiguous or you're unsure, put it in its own solo group

     ${productContext ? `Seller context: "${productContext}"` : ""}

     Respond with JSON:
     {
       "groups": [
         {
           "label": "Short product description (e.g. 'Blue Denim Jacket')",
           "imageIndices": [0, 3, 7],
           "confidence": "high" | "medium" | "low"
         }
       ]
     }

     imageIndices are 0-based indices referring to the order images appear in this message.
     Every image index must appear in exactly one group. Do not skip any.
     ```
   - User message: `"Group these {N} product images by product. Image indices are 0-{N-1} in the order shown. JSON only."`
   - Each image as: `{ type: "image_url", image_url: { url: "data:{mimeType};base64,{base64}" } }`

4. After each batch completes, map batch-local indices back to global indices (batch 0 images are indices 0-14, batch 1 are 15-29, etc.).

5. After ALL batches are processed, do a MERGE pass:
   - If there are multiple batches, the groups from different batches may describe the same product. Do a second GPT call that takes the group labels from all batches and asks GPT to merge groups with similar labels.
   - System prompt for merge: "You have product groups from multiple batches. Merge groups that clearly describe the same product. Return JSON: { mergedGroups: [{ label: string, sourceGroupIds: number[] }] } where sourceGroupIds reference the 0-based index of each group in the flat list."
   - If only 1 batch, skip the merge pass.

6. Stream each final group as an SSE event:
   ```
   data: {"type":"group","group":{"label":"Blue Denim Jacket","imageIndices":[0,3,7],"confidence":"high"}}\n\n
   ```

7. After all groups streamed, send done event:
   ```
   data: {"type":"done","totalGroups":N}\n\n
   ```

8. On error: if headers already sent, write `data: {"type":"error","message":"..."}\n\n` and end. Otherwise return 500 JSON.

**Important implementation notes:**
- Use `parseInt(String(req.params.id))` pattern if accessing params (consistent with existing handlers).
- Wrap the entire handler in try/catch.
- The endpoint does NOT save anything to the database -- it only returns grouping suggestions. The client will use these to populate the Group[] state.
- For the batch vision calls, do NOT use streaming (`stream: true`) -- use standard completion since we need the full JSON response to parse group assignments.
- Limit base64 image sizes: if any single image base64 string is over 1MB, resize by truncating (or just skip with a warning in the response). In practice, the client will handle resizing before sending.
