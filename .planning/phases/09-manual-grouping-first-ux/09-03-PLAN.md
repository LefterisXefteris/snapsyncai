Two coordinated edits to upload-zone.tsx:

**Edit A — Wire useGroupSelection (GROUP-07):**

1. Import: `import { useGroupSelection } from "@/hooks/use-group-selection";`
2. Inside the component, compute `orderedItemIds` with `useMemo(() => groups.flatMap(g => g.items.map(i => i.id)), [groups])`.
3. Call `const { selected, handleClick: handleThumbnailClick, clear: clearSelection, setSelected } = useGroupSelection(orderedItemIds);`
4. Replace the existing local `selectedIds` state (if any survived Plan 02) with `selected` from the hook. Delete the old simple-toggle handler.
5. Pass `selected` (as `Set<string>`) into `SortableThumbnail` as the existing `isSelected` check (`selected.has(item.id)`).
6. Pass `handleThumbnailClick` into `SortableThumbnail`'s onClick so it receives `(id, event)`. The thumbnail should call `onClick(item.id, e)` and stop propagation.
7. **Focused group tracking (for Cmd+A):** Add `const [focusedGroupId, setFocusedGroupId] = useState<string | null>(null);`. When `handleThumbnailClick` fires, also call `setFocusedGroupId(group.id)` (the SortableThumbnail onClick callback should receive the parent group id and forward it — either via a closure in the map or a new `groupId` prop on SortableThumbnail). This way the "focused group" == "the group containing the last-clicked thumbnail".
8. Add a `useEffect` that listens on `document` for `keydown` with a single handler that dispatches on `e.key`:
   - `Escape` → `clearSelection()`, `setFocusedGroupId(null)`
   - `a` or `A` when `(e.metaKey || e.ctrlKey)` and `focusedGroupId !== null` → `e.preventDefault()` (stop browser select-all), look up the focused group in `groups`, then `setSelected(new Set(focusedGroup.items.map(i => i.id)))`. If `focusedGroupId` is null (no group clicked yet), do nothing and let the browser default run.
   - Clean up the listener on unmount. Dependency array must include `[groups, focusedGroupId, clearSelection, setSelected]`.
9. In `handleDragStart`: if the dragged item is in `selected` and `selected.size > 1`, preserve the selection through the drag (do not clear). If the dragged item is NOT in `selected`, call `clearSelection()` then select only the dragged id. This lets the user grab a single un-selected thumbnail without losing range intent.
10. **handleDragEnd branching — CRITICAL for Phase 5 hero-reorder regression safety:**
    - **Branch 1 — Intra-group single-item reorder (PRESERVED, NO CHANGES):** If `active.id` and `over.id` resolve to the SAME source/target group AND `selected.size <= 1`, fall through to the EXISTING `arrayMove(group.items, oldIndex, newIndex)` path verbatim. This is the Phase 5 hero-reorder path (first thumbnail in a group is the hero, drag-reordering within a group re-elects the hero). Do NOT replace or refactor this branch — the Phase 5 tests and UAT depend on its exact behavior.
    - **Branch 2 — Cross-group OR batch move (NEW):** Only when the source group differs from the target group, OR when `selected.size > 1`, trigger the new batch-move logic: move ALL selected items (not just `active.id`) to the target group, preserving their relative order. Use the existing two-step overId resolution (keep the `find(g => g.id === overId) ?? find(g => g.items.some(i => i.id === overId))` pattern from RESEARCH Pitfall 2).
    - Clear selection after a successful cross-group batch move. Do NOT clear selection after an intra-group single reorder (Phase 5 behavior is unchanged, so selection state should also be unchanged).
11. After a successful drop that moved an item out of a group, if the source group becomes empty, leave the empty-group cleanup logic unchanged (Plan 04 handles that).
