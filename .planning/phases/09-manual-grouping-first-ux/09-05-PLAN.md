**Requirements for the new handler:**

1. Preserve `CONCURRENCY = 2` (per RESEARCH Pitfall 3). Use a for-loop over `groups` in batches of 2, awaiting each batch's `Promise.all`.
2. For each group, call:
```typescript
await uploadMutation.mutateAsync({
  files: group.items.map(it => it.file),
  groupAsOne: group.items.length > 1,
  hideToast: true,
});
```
   Do NOT pass `productContext` or `brandTone`.
3. On per-group success, call `deleteBlob(it.id)` for every item in the group. Do this inside the try, before the catch can fire for this group.
4. On per-group failure, catch the error, `console.error("[upload-zone] group upload failed:", err)`, and push the group into a local `failed: Group[]` array.
5. Track progress via `setUploadProgress(prev => ({ ...prev, current: prev.current + 1 }))` in a `finally` block so both success and failure advance the counter.
6. **After all batches settle — this is the sequence, do ALL of it:**
   - `setGroups(failed)` — only failed groups remain in React state.
   - `await saveGroups(failed)` — persist failed-only state to IDB.
   - **`setFailedGroupIds(new Set(failed.map(g => g.id)))`** — CRITICAL: populate the failedGroupIds set from the settled `failed` array. Without this line the Retry buttons never render and GROUP-10 silently breaks. This must happen before the toast fires so the UI is consistent when the user reads the toast.
   - If `failed.length === 0`, call `clearAll()`, call `setFailedGroupIds(new Set())` (reset), and show a success toast (`"${groups.length} products created"`).
   - If `failed.length > 0`, show a destructive toast: `"${failed.length} of ${groups.length} groups failed. Click Retry on each."`.

**Inline Retry affordance:**

7. Add a new state `const [failedGroupIds, setFailedGroupIds] = useState<Set<string>>(new Set())` — parallel to the groups array, does not touch the shared `Group` interface in `use-staged-images.ts`.
8. In the DroppableGroup header, when `failedGroupIds.has(group.id)` is true, render a red "Retry" button with `data-testid="retry-group-${group.id}"`. On click, call `retryGroup(groupId)` which:
   - Re-fires the single-group upload (same try/catch/deleteBlob logic as the main handler's per-group branch).
   - **On retry success:** remove `groupId` from `failedGroupIds` via `setFailedGroupIds(prev => { const next = new Set(prev); next.delete(groupId); return next; })`, remove the group from `groups` via `setGroups(prev => prev.filter(g => g.id !== groupId))`, and persist the new `groups` to IDB via `saveGroups`. If `groups` becomes empty after removal, also call `clearAll()`.
   - **On retry failure:** leave `failedGroupIds` unchanged (the id stays so the Retry button stays), show a destructive toast.
9. Make failed groups visually distinct: add a `border-destructive` class (or similar Tailwind treatment) conditional on `failedGroupIds.has(group.id)` so the user sees which groups still need attention.
10. Leave the existing `<ShinyButton>` "Confirm" button in place but update its label to reflect the count of remaining groups: `Confirm & Create ${groups.length} Product${groups.length === 1 ? "" : "s"}`.
