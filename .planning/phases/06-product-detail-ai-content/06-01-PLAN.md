    Insert a new route handler immediately before the `return httpServer;` line (line ~3098) in server/routes.ts.

    **Endpoint: POST /api/images/:id/generate-content**

    Request body:
    ```typescript
    { category: string; styleTone: string; audience: string }
    ```

    Implementation steps:
    1. Parse `id` from params. Load image via `storage.getImage(id)`. Verify `image.sessionId === getUserId(req)` — return 404 if not.
    2. Load image buffer via `loadImageBuffer(image)`. If null, return 400 `{ message: "Image not available for AI analysis" }`.
    3. Set SSE headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`.
    4. Build the multimodal prompt. The system message:
       ```
       You are an expert e-commerce copywriter. Generate product listing content for a product shown in the image.
       Output ONLY valid JSON with this exact structure (no markdown, no code fences):
       {
         "title": "Product title — specific, benefit-led, max 80 chars",
         "description": "3-4 paragraph product description, engaging and conversion-optimised",
         "seoKeywords": ["keyword1", "keyword2", ...],
         "aeoFaqs": [{"q": "Question?", "a": "Answer."}, ...]
       }
       Rules:
       - seoKeywords: 8-12 specific keywords/phrases for Shopify/Etsy/Amazon search — brand, material, use case, style
       - aeoFaqs: 4-6 FAQ pairs that answer common buyer questions about this type of product (price not included)
       - Use the category, style/tone, and target audience provided by the user
       ```
    5. User message content array:
       ```typescript
       [
         {
           type: "text",
           text: `Category: ${category || image.category || "General"}\nStyle/tone: ${styleTone}\nTarget audience: ${audience}\nProduct title context: ${image.title || image.originalName}`
         },
         {
           type: "image_url",
           image_url: { url: `data:${image.mimeType};base64,${buf.toString("base64")}` }
         }
       ]
       ```
       If the product group has multiple images (`image.productGroupId`), load up to 3 group images via `storage.getImagesByGroup(image.productGroupId)` (or fallback to single image if method unavailable — check storage.ts first). Add each as an additional `image_url` content part.
    6. Call `openai.chat.completions.create` with `model: "gpt-5.2"`, `stream: true`, `max_completion_tokens: 1500`, no `response_format` (stream does not support json_object mode).
    7. Stream chunks: for each chunk, if `chunk.choices[0]?.delta?.content` has text, write `data: ${JSON.stringify({ content })}\n\n`.
    8. After stream ends, write `data: ${JSON.stringify({ done: true })}\n\n` and `res.end()`.
    9. Wrap in try/catch. If headers already sent on error, write `data: ${JSON.stringify({ error: "Generation failed" })}\n\n` and end; otherwise `res.status(500).json(...)`.

    **Endpoint: POST /api/images/:id/regenerate-field**

    Request body:

    ```typescript
    { field: "title" | "description" | "seoKeywords" | "aeoFaqs"; category?: string; styleTone?: string; audience?: string }
    ```

    Same auth/image load pattern. Same SSE header setup. Build a targeted system prompt for the specific field:
    - `title`: "Generate a single product title. Output only the title text, no JSON, no quotes."
    - `description`: "Rewrite the product description — 3-4 engaging paragraphs. Output only the description text."
    - `seoKeywords`: "Generate SEO keywords as a JSON array of strings: [\"keyword1\", \"keyword2\", ...]. Output only the JSON array."
    - `aeoFaqs`: "Generate FAQ pairs as a JSON array: [{\"q\": \"...\", \"a\": \"...\"}]. Output only the JSON array."

    Use the same image content parts (single image is fine for regenerate). Stream the response the same way as generate-content. When `done`, write the done event and end.
