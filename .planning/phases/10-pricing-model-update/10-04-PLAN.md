<task type="checkpoint:human-action" gate="blocking">
  <action>Run the migration and archive admin endpoints in production. These are one-time irreversible actions.</action>
  <instructions>
    **IMPORTANT: Run these against your PRODUCTION environment, not localhost. Use your production URL and your production MIGRATION_SECRET.**

    **Prerequisites:**
    - Confirm `MIGRATION_SECRET` env var is set in Vercel (or your production host)
    - Have your production URL ready (e.g. https://your-app.vercel.app)
    - Deploy the Phase 10 changes to production first before running these commands

    ---

    **Step 1: Run the subscriber migration**

    This moves all active subscribers from their current price (monthly £9, annual £79, or old £19) to the new weekly £4 price. Uses `proration_behavior: 'none'` — no immediate charges, change takes effect at next billing date.

    ```bash
    curl -X POST https://YOUR_PRODUCTION_URL/api/subscription/migrate-to-weekly \
      -H "Content-Type: application/json" \
      -H "Cookie: <your auth cookie if requireAuth is enforced>" \
      -d '{"migrationSecret":"YOUR_MIGRATION_SECRET"}'
    ```

    Expected response:
    ```json
    { "migrated": N, "skipped": M, "errors": 0, "total": N+M }
    ```

    - `migrated`: subscribers who were moved to the weekly price
    - `skipped`: subscribers already on weekly or with no subscription item found
    - `errors`: must be 0; if non-zero, check server logs before proceeding

    If `errors > 0`, stop and investigate before running the archive step.

    ---

    **Step 2: Verify migration in Stripe Dashboard**

    - Open Stripe Dashboard → Customers
    - Check 2–3 migrated subscribers — their subscription should show the new weekly price
    - Confirm `proration_behavior: none` means no unexpected invoices were generated

    ---

    **Step 3: Run the price archive**

    This sets `active: false` on all old subscription prices (monthly, annual) and all credit pack prices. Existing subscriptions on those prices continue billing normally — archiving only prevents NEW subscriptions from using them.

    ```bash
    curl -X POST https://YOUR_PRODUCTION_URL/api/subscription/archive-old-prices \
      -H "Content-Type: application/json" \
      -H "Cookie: <your auth cookie if requireAuth is enforced>" \
      -d '{"migrationSecret":"YOUR_MIGRATION_SECRET"}'
    ```

    Expected response:
    ```json
    { "archived": ["price_xxx", "price_yyy", ...], "archivedCount": N, "skipped": M }
    ```

    - `archivedCount`: number of prices archived (expect 2–5: old monthly, old annual, 3 credit pack prices)
    - `archived`: array of Stripe price IDs — note these for your records

    ---

    **Step 4: Verify archive in Stripe Dashboard**

    - Open Stripe Dashboard → Products
    - Check the old subscription product — its monthly and annual prices should show as "Archived"
    - Check credit pack products — their prices should show as "Archived"
    - Confirm the NEW weekly and annual prices are still active

    ---

    **Step 5: Credit balance refund check (REQUIRED — not optional)**

    Users who purchased credit packs before this migration are owed refunds for any unused balance. You must complete this step before typing "migration-complete".

    - Open Stripe Dashboard → Customers
    - Filter or search for customers with credit pack charges (look for one-time payments rather than subscriptions)
    - For each customer with a recent credit pack purchase, calculate their unused balance and issue a partial refund via Stripe Dashboard → Payment → Refund (use 45p/credit as the refund rate — most user-favorable)
    - Record the customer IDs and refund amounts issued

    **Confirmation required:** Before typing "migration-complete" below, you must confirm:
    - You have queried Stripe for all credit pack purchasers
    - You have issued refunds for any users with unused credit balances, OR confirmed that no users have outstanding balances requiring refunds

    If you are uncertain whether any users hold balances, err on the side of checking — this is a legal and trust obligation.
  </instructions>
  <resume-signal>Type "migration-complete" after Steps 1–5 are done. Confirm in your message that the credit balance refund check was completed (e.g. "migration-complete — refund check done, N customers refunded" or "migration-complete — no outstanding credit balances found").</resume-signal>
